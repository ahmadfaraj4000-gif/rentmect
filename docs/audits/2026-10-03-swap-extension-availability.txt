Findings and changes
The performance changes did not change the saved swap or extension dates. The dedicated swap form previously listed vehicles without availability indicators. The existing rental schedule trigger checked the preceding rental's turnaround but omitted the proposed rental's turnaround before a following reservation. The old swap conflict helper relied on assignment rows without a fallback for a reservation missing those rows.

Migration 20261003223000_vehicle_conflict_checks adds a shared conflict reader used by booking availability, rental/checkout guards, and swap/extension checks. It includes assignment history, live rental end times, reservation fallback, three-hour turnaround on both sides, checkout holds, calendar blocks, maintenance locks, and existing physical-return lock rules. It also prevents releasing a vehicle to another active customer before physical return. Existing guarded apply actions recheck availability at confirmation while retaining their vehicle advisory lock.

New admin_rental_vehicle_availability requires admin rental.edit permission. Its detailed conflict records are not exposed to anonymous/customer callers. Public fleet availability retains generic reasons. The internal conflict helper cannot be invoked by public, anon, or authenticated roles directly.

Admin commit a3d0b67 adds availability checks only inside the existing swap and extension dialogs. Swap choices show Available/Unavailable for the chosen time window and disable unavailable vehicles. Extensions show conflict times and the next booked reservation. A changed window immediately invalidates the previous availability result; late or failed reads cannot enable confirmation. The original rental-card interface and filter-scoped loading remain intact.
