Rental workspace performance rollout — October 3, 2026

Deployed backend migration: 20261003190000_admin_rental_workspace_reads

Admin source commits: 2ee6637, 4eea5f9
Successful deployments: 37147846728, 37147928130
Live entry asset after final deployment: index-CPWRW1-7.js

Changes
- Rentals owns a paginated, server-filtered summary list; opening the main tab defaults to Needs Action.
- One list RPC replaces approximately 20 full-domain reads on initial entry.
- Full rental documents, payment records, refunds, extensions, and reports load only when a rental is opened.
- Existing operational/financial forms use complete hydrated records; controls do not mount before the detail read succeeds.
- Mutations refresh the selected rental; list/count refresh runs independently of save completion.
- Event bursts share a refresh; events carrying another rental's ID do not reload the selected rental.
- Pages are cached by filter, search, focus ID, and offset for 30 seconds, with invalidation on changes. Delayed reads cannot replace a different selection.
- Archive requests pages of 25 from the database.
- Read endpoints use SECURITY INVOKER and existing RLS; no billing calculation, payment mutation, or return-approval guard was replaced.

Evidence
The old rental and document query shapes alone serialized approximately 6,180,630 bytes of uncompressed JSON across 104 rentals (92 archived) and 168 documents. This excludes other initial queries and is not a compressed network-transfer measurement.
The new initial Needs Action response measured 4,108 bytes; Ayleen's detail response measured 30,940 bytes. Authenticated database execution of the list measured 225.423 ms in one EXPLAIN ANALYZE run.
In one live Chrome check, clicking Rentals until the Needs Action count was visible took 557 ms. Opening Ayleen until Payment Summary was visible took 750 ms. These are individual observations including automation overhead, not percentile benchmarks or guarantees.
All eight live filter counts matched before/after: Needs Action 5, Ready for Pickup 0, Cars Out 12, Returns Today 4, Extensions Pending 1, Maintenance 1, All Open 12, Archive 92.
Ayleen's displayed balance remained $68.06; deposit held remained $400. Extension dialog opened and was cancelled without saving. Both live archive pages showed 25 records. No live browser errors appeared.

Interface correction after user feedback — October 3, 2026
Admin commit: 4b929e2
The original rollout changed the rental interface beyond the requested load-time work. That redesign was removed: the original RentalRow cards, direct action buttons, minimized inline details, warning popup, and Archive "Load 25 more archived rentals" interaction are restored. The separate summary list, Open rental step, selected-rental section, automatic scrolling, and previous/next navigation are removed.

Reads remain scoped to the selected filter. Its cards receive complete detail records before rendering; detail reads run at concurrency five and reuse the session cache. Archive loads an additional 25 records when requested. Switching filters discards late results and stops queued detail reads for the prior filter. Saves refresh the interacted-with card without awaiting the filter refresh. The earlier list-only/on-open timing observations above describe the superseded interface, not this corrected version.

Validation: 75 focused tests passed, including new behavioral tests for complete inline hydration, stale-filter suppression, archive accumulation/cache reuse, failed financial reads, save refresh independence, and bounded concurrency. Production build passed. Synthetic browser verified the original card controls, inline expansion and $68.06 balance, and Archive accumulation from 25 to 50 cards. No financial mutations were performed.

All eight filter counts remained unchanged.
